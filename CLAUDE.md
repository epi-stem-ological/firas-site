# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (Node >= 18). There are no tests in this project.

```bash
pnpm install        # install dependencies
pnpm dev            # start Next.js dev server
pnpm build          # production build (also generates content-collections)
pnpm start          # serve the production build
pnpm lint           # ESLint
pnpm lint:fix       # ESLint with --fix
```

## Architecture

This is a Next.js 16 (App Router) + React 19 + Tailwind CSS v4 personal site, forked from
`dillionverma/portfolio`. The home page is one long single-page resume; `/blog` and `/blog/[slug]`
render MDX posts.

### Single source of truth: `src/data/resume.tsx`

Almost every section on the home page (`src/app/page.tsx`) and the navbar/footer dock
(`src/components/navbar.tsx`) reads from the exported `DATA` object in `src/data/resume.tsx`. Skill
icons, work history, education, hackathons, projects, contact/social links, and site metadata
(`name`, `url`, `description` used by `src/app/layout.tsx`'s `metadata`) all live there. Content
edits to the resume should happen in this file rather than in the page components.

Skill and social icons are React components imported from `src/components/icons.tsx` and
`src/components/ui/svgs/*` and stored as `icon` references on the data — the components iterate
those refs and render `<skill.icon />`.

### Blog content pipeline (`content-collections`)

MDX posts live in `content/*.mdx`. They are processed at build/dev time by
`@content-collections/next` (configured in `content-collections.ts`) into a generated module that
consumers import as `content-collections` (TS path alias → `./.content-collections/generated`).

- Frontmatter schema is enforced by zod in `content-collections.ts`. Required: `title`,
  `publishedAt`, `summary`. Optional: `updatedAt`, `author`, `image`.
- Posts are compiled with `remarkGfm` plus the local `remarkCodeMeta` plugin
  (`src/lib/remark-code-meta.ts`), which copies fenced-code `meta` strings (e.g. `title="foo.ts"`)
  onto `data-meta` / `data-title` HAST properties so the client `CodeBlock` can render filenames.
- `withContentCollections` **must be the outermost plugin** in `next.config.mjs`.
- `.content-collections/` is gitignored — it is regenerated by `pnpm dev` / `pnpm build`. If
  imports from `content-collections` fail, run a build/dev once to generate it.

### Blog rendering and routes

- `src/app/blog/page.tsx` lists posts using the shared pagination helpers in
  `src/lib/pagination.ts` (page size 5, `?page=` query param).
- `src/app/blog/[slug]/page.tsx` finds posts by stripping `.mdx` from `post._meta.path`,
  generates `generateStaticParams`, builds JSON-LD, and renders MDX via
  `<MDXContent code={post.mdx} components={mdxComponents} />`.
- `mdxComponents` is defined in `src/mdx-components.tsx` and exposes `MediaContainer` (custom
  image/video block) plus styled overrides for `pre`, `code`, `hr`, `table`. `pre` delegates to
  `src/components/mdx/code-block.tsx`, which is a `"use client"` component that re-highlights
  code in the browser using `shiki/bundle/web` (`github-light` / `github-dark`) and adds a
  copy-to-clipboard button. Server-rendered HTML therefore intentionally contains the unhighlighted
  source until the effect runs.
- Both `src/app/opengraph-image.tsx` and `src/app/blog/opengraph-image.tsx` /
  `src/app/blog/[slug]/opengraph-image.tsx` use Next's image metadata convention to generate OG
  images per route.

### Styling and UI conventions

- Tailwind v4 via `@tailwindcss/postcss` (no `tailwind.config.ts`); design tokens live as CSS
  variables in `src/app/globals.css` and are exposed through the `@theme inline` block. Dark mode
  is class-based (`.dark`) via `next-themes` and `ThemeProvider` in `src/app/layout.tsx`.
- shadcn/ui is configured (`components.json`) with style `new-york`, base color `neutral`, RSC on,
  Lucide icons. Generated primitives go in `src/components/ui/`. The `cn()` helper
  (`src/lib/utils.ts`) is the standard `clsx` + `tailwind-merge` combiner used everywhere.
- "magicui" animation primitives (`BlurFade`, `BlurFadeText`, `Dock`, `FlickeringGrid`) live in
  `src/components/magicui/` and are used heavily on the home page with a staggered
  `BLUR_FADE_DELAY` pattern.
- Page sections are split into `src/components/section/*` (work, projects, hackathons, contact)
  and composed by `src/app/page.tsx`.

### Path aliases

`tsconfig.json` defines:

- `@/*` → `./src/*`
- `content-collections` → `./.content-collections/generated`

Use `@/` imports for everything in `src/`.

### Security headers

`next.config.mjs` sets `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, and a
`Permissions-Policy` that disables camera/microphone/geolocation on every route. Preserve these
when editing the config.

### Lint configs

There are two ESLint config files: the flat config `eslint.config.mjs` (used by `pnpm lint`,
extends `eslint-config-next/core-web-vitals`) and a legacy `.eslintrc.json`. The flat config is
the active one; treat the legacy file as historical.
